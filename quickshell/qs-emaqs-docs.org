#+title: emaqs — an Emacs-workspace pill for Quickshell

* What this is
=emaqs= is a second, small Quickshell overlay — a sibling of the =pill= (see
[[file:qs-pill-docs.org][=qs-pill-docs.org=]]) — that surfaces the running *Emacs
daemon's Doom workspaces* at the bottom of the screen. Like the pill, the code
lives as plain files in [[file:emaqs/][=emaqs/=]] (this repo) — edit those, then run
[[file:emaqs/deploy.sh][=emaqs/deploy.sh=]] to validate and copy them to the live config at
=~/.config/quickshell/emaqs/=. (This file used to tangle the code; the blocks
were broken out into =emaqs/= in Aug 2026 — nothing here generates code any
more.) This file keeps the design notes: one section per source file.

At rest it is a single up-chevron tab attached to the bottom edge (translucent,
dimmed). Hovering it opens a horizontally-centred bar of *workspace names*; a hover
highlight slides between names and a focus highlight marks the *current* workspace,
both animating between positions exactly like the pill's shared hover square.

- *Left-click* a workspace name → switch Emacs to that workspace *and* raise/focus
  the Emacs frame.
- *Right-click* a workspace name → the bar grows into a rectangular menu (a
  [[file:qs-pill-docs.org::*MenuHeader.qml][=MenuHeader=]]-style header with a back
  chevron and the workspace name as title) listing that workspace's *buffers*,
  grouped and sorted *exactly like the ~SPC SPC~ super-menu* (Buffers / Agent Shell /
  Ghostel — files, directories and actions are intentionally left out). Clicking a
  buffer switches to that workspace + buffer and focuses Emacs. Opposite the header
  sit two icons: *magit* (opens =magit-status= for the workspace's project root) and
  *close* (a confirmation sub-panel, then deletes the workspace).

Everything is driven over =emacsclient= through [[*emaqsbridge.py][=emaqsbridge.py=]],
reusing the *user's own* super-menu predicates (=mp/normal-buffer-p=,
=mp/agent-shell-buffer-p=, =mp/ghostel-buffer-p=) and =buffer-name-history= ordering,
so the buffer list matches Emacs 1:1 with no logic duplicated here. If the daemon is
down every query returns empty and the bar simply shows nothing — best-effort, never
blocks.

emaqs is also the *agent-shell surface*: Emacs no longer sends agent-shell turns to the
freedesktop daemon (the pill) — they are pushed here over DBus by
[[*agentbridge.py][=agentbridge.py=]] and rendered in the pill itself (permission
Allow/Deny cards, an "agent finished" line, a bouncing-dots "working" chevron and a
per-workspace pulse), so they never appear in the pill's notification popups or
history. See [[*AgentBridge.qml][=AgentBridge=]] and, on the Emacs side,
=doom/config.org= ▸ *Agent Shell* ▸ *Desktop Notifications*.

* Environment (verified, not assumed)
Confirmed against the running daemon on this machine (2026-07):
- =(+workspace-list-names)= / =(+workspace-current-name)= — workspace enumeration.
- =(+workspace-switch NAME)= — switch (=name &optional auto-create-p=).
- =(+workspace-buffer-list &optional PERSP)= — a *specific* workspace's buffers
  without switching to it (so right-clicking a name lists its buffers in place).
- =(+workspace-delete WORKSPACE)= — close a workspace.
- =(magit-status ROOT)=, =(projectile-project-root)=, =(vc-root-dir)= — magit entry.
- =mp/normal-buffer-p=, =mp/agent-shell-buffer-p=, =mp/ghostel-buffer-p=,
  =consult--buffer-query=, =buffer-name-history= — the super-menu grouping/sorting.

*Known limitations (same as the pill, documented so they aren't surprises):*
- *Blur*: this is *alpha translucency + a gradient*, not true backdrop blur — the KWin
  blur protocol is not exposed to Quickshell (identical to the pill's resting state).
- *Focusing the Emacs frame* mirrors the pill's =pill-open= (=make-frame-visible= +
  =raise-frame= + =select-frame-set-input-focus=); it is subject to KWin's
  focus-stealing prevention just as the pill's agenda-open is.
- *Live updates* are *polled* (=emacsclient= every 1.2 s) and *only while the bar is
  expanded or a menu is open* — at rest (the collapsed chevron) nothing is polled, so
  it is idle-cheap. A switch you make from the bar is applied optimistically so the
  focus highlight moves immediately; external switches (from inside Emacs) catch up on
  the next poll.

** EmaqsBridge.qml
*** Description
The Emacs-daemon state object (the analogue of the pill's [[file:qs-pill-docs.org::*OrgAgenda.qml][=OrgAgenda=]]).
Instantiated once in init.qml as =EmaqsBridge { id: emacs }=. Holds the workspace
=names= + =current= (so =currentIdx= drives the focus highlight) and the grouped
=bufferGroups= for the menu; every method shells out to [[*emaqsbridge.py][=emaqsbridge.py=]].
Loading is lazy — =loadWorkspaces= runs when the bar opens (and after a close),
=loadBuffers= when a workspace is right-clicked; nothing polls. =switchTo= updates
=current= optimistically so the focus highlight moves at once. After a =closeWorkspace=,
=Reloadtimer= re-syncs the workspace list a beat later, once Emacs has processed the
delete. =setAgentSession(buffer, kind, value)= changes an agent-shell buffer's model
or session mode from the menu's per-buffer pickers — it optimistically rewrites that
buffer's entry in =bufferGroups.sessions= (so the picker reflects the pick at once)
then dispatches =emaqsbridge.py agent-session= on its own =sessProc=.
*** Code
Code: [[file:emaqs/EmaqsBridge.qml][=emaqs/EmaqsBridge.qml=]]

** emaqsbridge.py
*** Description
The Emacs backend, one Lisp =(progn …)= of =emaqs-…= helpers prepended to every call
(so no =.el= on the load-path), talking to the running daemon over =emacsclient= —
mirrors [[file:qs-pill-docs.org::*orgbridge.py][=orgbridge.py=]]. Commands:
- =workspaces= → JSON ={ "names": […], "current": "…" }=.
- =buffers [WS]= → JSON =[{ "group": "Buffers"|"Agent Shell"|"Ghostel", "items": […] }]=
  for workspace =WS= (default current), grouped/sorted like the =SPC SPC= super-menu.
  The *Agent Shell* group additionally carries =sessions=, a map keyed by buffer name
  → ={ models:[{token,label}], modes:[…], model, mode }= read live from each shell's
  =agent-shell--state=, so the menu can render its per-buffer model/mode pickers.
- =switch NAME= → switch to workspace =NAME=, raise + focus the Emacs frame.
- =openbuf NAME WS= → (switch to =WS= if needed then) show buffer =NAME=, raise + focus.
- =magit WS= → =magit-status= at =WS='s project root, raise + focus.
- =close WS= → kill workspace =WS= (=+workspace/kill=, killing its buffers too).
- =agent-action ID KEY= → dispatch a permission Allow/Deny (or a body-click switch)
  back into the agent-shell responder closure stashed in the user's config.
- =agent-session BUF KIND VALUE= → set agent-shell buffer =BUF='s model (=KIND=
  ="model"=) or session mode (="mode"=) to option id =VALUE= (from a permission-card
  or workspace-menu picker). The setter (=mp/agent-shell-emaqs-set-session=) lives in
  the user's config, so these two agent commands skip the =emaqs-…= Lisp prelude.

The buffer grouping *reuses the user's own super-menu predicates* when present
(=mp/normal-buffer-p= etc.) and falls back to simple checks otherwise, so the list
matches Emacs with nothing duplicated. =workspaces=/=buffers= write their JSON to a
temp file whose path Emacs returns (Unicode-safe, as in orgbridge). Best-effort — if
the daemon is unreachable the data commands print empty JSON.
*** Code
Code: [[file:emaqs/emaqsbridge.py][=emaqs/emaqsbridge.py=]]

** PillSurface.qml
*** Description
The bar/tab background as a =Shape= instead of a plain rounded =Rectangle=, so it can
sit *flush against the screen's bottom edge* with *"rounded out" corners*: the top
corners are convex (normal rounding) while the two bottom corners are *concave wings*
that flare outward into the screen edge (the caelestia look from the reference). The
bottom edge itself is straight. =radius= is the top convex corner; =wing= is the
bottom concave flare; both animate (=Behavior=) so the tab→bar→menu morph stays
smooth. Resting vs. active look is just =fillColor= / =strokeColor= / =strokeWidth=
passed in (a translucent fill at rest, a solid fill + hairline border when active) —
no gradient, so it needs no shape-gradient type.
*** Code
Code: [[file:emaqs/PillSurface.qml][=emaqs/PillSurface.qml=]]

** fswatch.py
*** Description
A minimal fullscreen watcher — emaqs's own tiny slice of the pill's
[[file:qs-pill-docs.org::*winbridge.py][=winbridge.py=]], reporting *only* whether the
focused window is fullscreen so the resting tab can auto-hide (games / video), exactly
like the pill's =fsHide=. KWin (Wayland) exposes no active-window / fullscreen state
over DBus, so a 6-line KWin script calls back into our own service on
=windowActivated= and =fullScreenChanged=. It uses *emaqs-specific* names — DBus name
=org.kde.emaqs=, KWin plugin =quickshell-emaqs-active= — so it never collides with the
pill's =org.kde.pill= / =quickshell-pill-active= when both run at once. Prints one JSON
line =\{ "fullscreen": bool \}= per change on stdout; the script is unloaded on exit.
*** Code
Code: [[file:emaqs/fswatch.py][=emaqs/fswatch.py=]]

** agentbridge.py
*** Description
The *agent-shell push channel*. Agent-shell turns no longer go through the
freedesktop daemon (the pill) at all; instead the Emacs config
([[file:../doom/config.org::*Desktop Notifications][=config.org= ▸ Desktop
Notifications]]) pushes them to emaqs over DBus. This tiny service — a sibling of
[[*fswatch.py][=fswatch.py=]] — *owns* the bus name =org.kde.emaqs.agent= (its own
name, so it never clashes with =org.kde.emaqs= / the pill) and turns the three
methods Emacs calls into one JSON line each on stdout, which [[*AgentBridge.qml][=AgentBridge=]]
reads:
- =Notify(id, kind, buffer, workspace, title, body, actions_json)= → a
  permission-request (=kind="permission"=, =actions= = =[[key,label],…]=) or a
  finished turn (=kind="finished"=). *Its 7-argument signature is frozen* — never
  extend it, or an Emacs/bridge version skew would reject every notification.
- =Meta(id, meta_json)= → *optional, additive* card enrichment, sent by Emacs
  *just before* the matching =Notify=. The bridge stashes it by =id= and folds it
  into that =Notify='s emitted =meta= (and also emits a standalone =\{"op":"meta"\}=
  so an already-shown card refreshes). =meta_json= is a small JSON object: the
  permission's *operation type* (=optype= — the ACP tool-call kind, e.g. ="execute"=
  / ="read"= / ="edit"= / ="fetch"=, so the card can say *what* is being asked), the
  available *models/modes* (=models=/=modes= as =[{token,label}]=) with the current
  pick (=model=/=mode=) for the in-card dropdowns, and the finished turn's =elapsed=
  prompt time. Because it is a separate method, an old Emacs that never calls it — or
  an old bridge that lacks it — simply yields a card with no extra data, never a
  broken one.
- =Close(id)= → drop the notification with that id (the agent answered elsewhere).
- =Working(buffer, workspace, "1"|"0")= → the shell started / stopped working.

One-way (Emacs → emaqs); the reverse path — Allow/Deny/switch — goes back through
=emaqsbridge.py agent-action=, and a model/session-mode change from the permission
card's dropdowns through =emaqsbridge.py agent-session=. Best-effort: if emaqs (this
service) is down, Emacs's async calls simply get an unowned-name error and drop.
*** Code
Code: [[file:emaqs/agentbridge.py][=emaqs/agentbridge.py=]]

** AgentBridge.qml
*** Description
The agent-shell state object (a sibling of [[*EmaqsBridge.qml][=EmaqsBridge=]]),
instantiated once in init.qml as =AgentBridge { id: agent }=. It runs
[[*agentbridge.py][=agentbridge.py=]] as a long-lived =Process= and folds its JSON
lines into three reactive pieces of state:
- =notifs= — the live notification cards (=kind= = ="permission"= or ="finished"=),
  keyed by =id= (=upsert=/=remove= on =notify=/=close=). Each carries a =meta= object
  (operation type, elapsed time, model/mode option lists + current pick).
  =permissionNotif= / =finishedNotif= expose the newest of each for the collapsed morph.
- =workingList= — one entry =\{buffer, workspace\}= per shell currently working;
  =workingCount= drives the three-dots chevron and the left-of-title badge, and
  =workspaceWorking= drives the per-workspace pulse in the expanded bar.
- =dnd= — the emaqs-local *do-not-disturb* toggle (the bell button in the bar). When
  set, init.qml hides every agent visual; it does *not* tell Emacs, so the in-buffer
  dialog still works.

Buttons dispatch back to Emacs via =action(id, key)= → =emaqsbridge.py agent-action=;
=dismiss(id)= just drops the card locally (an unanswered permission is still
answerable inside Emacs). =setSession(id, buffer, kind, value)= changes a shell's
model or session mode from the permission card's dropdowns — it optimistically updates
the local notif =meta= (so the picker reflects the choice immediately, since the daemon
won't re-=Notify= for the same request) then dispatches =emaqsbridge.py agent-session=.
This object polls nothing — it is purely push-driven, so it is idle-cheap when no agent
is running.

** init.qml
*** Description
The overlay itself: one full-screen layer-shell =PanelWindow= per monitor (reserving
no space, click-through except over the tab), morphing through three stages —
*collapsed* (an up-chevron tab flush at the bottom), *expanded* (the workspace bar,
opened by *clicking* the tab — "focus mode": it stays open until a click elsewhere
moves focus away), *menu* (the right-click buffer menu). It composes [[*Theme.qml][=Theme=]],
[[*MSym.qml][=MSym=]], [[*MenuHeader.qml][=MenuHeader=]] and [[*EmaqsBridge.qml][=EmaqsBridge=]].

*Screen-share DND indicator.* emaqs detects a live screencast independently of the
pill (its own =PipeWire= scan for a =Stream/Output/Video= node → =screenRecording=)
and shows its DND bell as "on" while sharing, mirroring the pill's auto-DND. This is
*indicator only*: agent-shell turns still surface as usual mid-share (they remain
gated by =agent.dnd= alone, which the screencast does *not* set), so a permission
request is never silently swallowed while presenting.

*Hover / focus highlights.* The workspace names are a =Row= of labels; two rounded
rectangles are drawn *behind* them — a *focus* highlight bound to the current
workspace's label geometry and a *hover* highlight bound to the pointed-at label —
each with =Behavior on x/width= so they glide between labels exactly like the pill's
shared hover square.

*Loading is lazy, not polled.* Nothing is fetched at startup, and there is no
timer. Workspaces are pulled *when the bar opens* (=onDashChanged= → =loadWorkspaces=)
and again *after a workspace is closed* (=reloadTimer= re-syncs a beat later, once
Emacs has processed the delete). Buffers are pulled *when a workspace is right-clicked*
(=openMenu= → =loadBuffers=). So the collapsed tab — and Emacs — stay untouched until
you actually interact.

*Agent-shell surfacing.* Fed by [[*AgentBridge.qml][=AgentBridge=]] (=agent=), the
*collapsed* tab morphs — in priority order — into a *permission card*, a one-line
*"buffer Agent finished! ✕"*, or three *bouncing dots* while any agent is working,
before falling back to the chevron. The permission card leads with an *operation-type*
eyebrow (icon + label derived from the tool-call =meta.optype= — "Run command" /
"Read files" / "Edit files" / "Send request" / …, so you see *what* is being asked at
a glance), then the buffer name and description, and a final row pairing two *icon
buttons* (model + session mode) on the left with *Allow*/*Deny* on the right (a body
click switches to the shell). The finished line appends *how long the whole prompt
took* (=meta.elapsed=, stamped at send and measured at turn-complete). The model/mode
icon buttons are the reusable =AgentPicker=: clicking one registers it as
=win.agentSel= and a single win-level overlay paints its option list above everything
(so it escapes the small card / the clipped menu), right-aligned and opening *upward*
when there's room; a pick calls =setSession= (permission card) or
=emacs.setAgentSession= (menu), applies immediately and leaves the surface up. The
*same* pickers sit next to every agent-shell buffer in the workspace right-click menu
(fed by that group's =sessions= map). All three morphs are click-through-safe (the
tab-expand click is disabled while a card shows, so its own buttons win); while a
picker list is open the window mask widens to the whole screen so the list is clickable
and a click-away closes it. In the
*expanded* bar, every working workspace's label gets a breathing accent *pulse*, a
trailing *do-not-disturb* bell mutes all agent visuals (emaqs-local — Emacs still
shows its in-buffer dialog), and a leading badge counts the working agents when more
than one runs. DND and fullscreen both suppress the tab, except a pending
permission/finished card, which always shows.

* Editing & deploying
The code lives in [[file:emaqs/][=emaqs/=]] (this repo); the live config at
=~/.config/quickshell/emaqs/= is a *copy* the running overlay loads from. No
symlinks, no tangling — edits change nothing live until you deploy:

1. Edit files in =emaqs/=.
2. Test with =emaqs/check.sh= — validation only, touches nothing live (python
   =ast= parse, =bash -n=, headless =QT_QPA_PLATFORM=offscreen qs -p init.qml=
   load). This is the *only* test step AI agents may run.
3. Run =emaqs/deploy.sh= — runs =check.sh=, then copies only the changed files
   to the live config; the running overlay reloads on its own. *User-only*:
   agents never deploy, even if asked — they stop and ask me to run it.

Never edit =~/.config/quickshell/emaqs/= directly — the next deploy would
overwrite it; copy hot-fixes back into =emaqs/= first. Run for real with
=~/.config/quickshell/emaqs/run-emaqs.sh=.
