* The brief (what I was asked to build)

Replace KDE's default panels with a Quickshell "pill":

- A *pill* at the *top-center*, *always on top*, *not* reserving screen space;
  hidden only when a fullscreen window is focused.
- *Collapsed*: only essential info — a notification transforms the pill;
  otherwise system tray + icons of open apps that have a notification, else time.
- *Hovered*: original info hides, pill transforms — *virtual-desktop dots*
  top-left (filled = focused, click to switch), *active apps* top-right (pin-able
  ideally), *system tray* below the apps, *time* below the desktops.
- *Clicked*: expands further into a *control panel*. The tray side always shows
  network/volume/bluetooth/battery/notification icons; clicking one swaps the
  pane below (default = notification history) for that icon's menu:
  - *network*: pick Wi-Fi + VPN like KDE's applet.
  - *volume*: Devices tab (mic + speaker) and Applications tab; pick the active
    device, change any volume.
  - *bluetooth*: connected on top, divider, paired, then discovered.
  - *battery*: battery of all supported devices.
- Clicking *outside* only collapses the pill; the click is *not* passed through.

Constraints: prefer KDE/system APIs over writing our own; review docs, don't
guess; if a thing can't be backed by a source, say so. Reference rice:
[[https://github.com/Gakuseei/Ricelin][Gakuseei/Ricelin]] (Hyprland-only — its
workspace/taskbar code does not port to KWin; design/animation ideas do).

*Critical compositor fact* (=wayland-info=): KWin advertises =zwlr_layer_shell_v1=
and =org_kde_plasma_virtual_desktop_management=, but NOT =ext_workspace_v1=,
=zwlr_foreign_toplevel_manager_v1=, or =org_kde_plasma_window_management=. So
Quickshell's =WindowManager= and =Wayland.ToplevelManager= exist but *don't
function* here — virtual desktops go through KWin DBus, and the taskbar /
fullscreen-hide are blocked on there being no client-visible window-list protocol.

The taskbar needs no Wayland window protocol: KWin's KRunner "windows" runner lists
and activates windows over DBus, and a tiny KWin script reports the active window
(see =winbridge.py=). Remaining: *launcher actions* (blocked on =DesktopEntries=
returning entries), *pinned apps* (app-side state), and *VPN* (needs nmcli).

* Taking over notifications from Plasma

The pill is now a *real* freedesktop notification daemon (=Quickshell.Services.-
Notifications.NotificationServer=, see [[*Notifications.qml][§ Notifications.qml]]).
Only one process may own the bus name =org.freedesktop.Notifications=, and *that
process must be chosen before the pill can receive anything*.

*Verified facts on this machine* (=busctl --user=, June 2026):
- =org.freedesktop.Notifications= is owned by *=plasmashell= itself* (the built-in
  =org.kde.plasma.notifications= system-tray applet, backed by
  =libnotificationmanager.so=) — there is no separate daemon to kill.
- Plasma registered the name *without* =DBUS_NAME_FLAG_ALLOW_REPLACEMENT=:
  requesting it with replace+allow-replacement returns =EXISTS= (code 3), so
  Quickshell *cannot* take it at runtime. Plasma must be stopped from registering
  it in the first place.

*How to disable Plasma's notifications* (then the pill grabs the name on its next
start):

1. Right-click the system tray ▸ *Configure System Tray…* ▸ *Entries*.
2. Set *Notifications* to *Disabled* (not "Shown"/"Hidden" — those still load the
   applet and grab the bus name; only *Disabled* skips instantiating it).
3. Restart the shell so the name is released, e.g.
   =systemctl --user restart plasma-plasmashell= (or log out / back in).
4. Start the pill (=./run-pill.sh=). Confirm it owns the daemon:
   =busctl --user call org.freedesktop.Notifications /org/freedesktop/Notifications
   org.freedesktop.Notifications GetServerInformation= should now report
   ="quickshell"= as the server name, not ="Plasma"=.

To hand notifications *back* to Plasma: re-enable the tray entry and restart
=plasma-plasmashell= (and stop the pill, or stop its server).

Caveat (unverified): if disabling the tray entry alone does not free the name on
your Plasma build, the fallback is to ensure the pill's =NotificationServer=
registers *before* plasmashell at login — but on this setup the tray-entry method
is the supported route, and the name-ownership facts above are confirmed.

* How the pill works

The shell is split into small files (see [[*File map][§ File map]]). Sibling
=.qml= files are usable as component types via QML's implicit directory import.
=Theme= is instantiated once in =init.qml= and passed to each menu as a =theme=
property (no singletons, so nothing magic to set up).

** Window & input model (init.qml)
=Variants { model: Quickshell.screens }= makes one =PanelWindow= per monitor. Each
window is a *full-screen* layer-shell =Overlay= surface that reserves no space.
Input is governed by the window =mask=:
- *collapsed / hovered*: =mask= = a =Region { item: pill }= → only the pill
  rectangle catches clicks; the rest of the screen passes through.
- *open / launcher / right-click menu*: =mask= = a =Region { item: backdrop }=
  (the whole window) → outside clicks are caught by a backdrop =MouseArea= that
  closes the panel, so the click is swallowed, never passed through.
- *fullscreen-hide* (=win.fsHide=): while a fullscreen window is focused and the
  pill is at true rest (not hovered/open and no notification morphing), the pill
  fades to =opacity 0= and =mask= = an *empty* =Region= → the whole window is
  click-through, so a game/video underneath is unobstructed. A notification still
  morphs the pill (=notifMorph= overrides =fsHide=), so alerts appear as usual.

** Stages
A single =pill= =Item= animates =width=/=height= between the stages via
=Behavior=; cross-fading content layers (=opacity= + =visible=) show/hide per
stage:
1. *collapsed* (96×28): just =hh:mm=.
2. *hovered* (=dash=, 384×104): dashboard — *two balanced rows*. Row 1: desktop
   dots (left) | grouped app icons (right). Row 2: an app-launcher button +
   date/time (left) | status icons
   (network/volume/bluetooth/battery/notifications, icon-only, click → open that
   menu) + system tray (right). =dash= is true when hovered, open, or a
   right-click menu is up.
3. *open* (470 tall): control panel. Both dashboard rows *stay visible* on top —
   Row 2 doubles as the *menu switcher* (the active menu's status icon is
   highlighted); there is *no icon rail*. Below a divider sits a single full-width
   menu pane: a =Loader= shows the menu component for =win.menu= (=active= only
   while open). Each menu renders a shared =MenuHeader= — a back chevron *and title*
   (both clickable) that collapse the panel via the menu's =closeRequested()= signal
   (wired through a =Connections= on the loader), plus a trailing slot for the
   menu's own toggles. Clicking the pill body opens to the *notification-history*
   pane (=win.menu = 4=, the default); a Row-2 status icon opens straight to its own
   menu and switches it while open.
4. *launcher* (=launcher=, 520×470): the app launcher takes the menu pane's place,
   *also below the two rows* (same divider + offset), so it matches the menus (see
   [[*Launcher.qml][§ Launcher.qml]]). Opened from the Row-2 grid button
   (=view-grid-symbolic=); while =open= or =launcher= the layer surface takes
   =WlrKeyboardFocus.OnDemand= so the search field can receive keystrokes.

The window =mask= also expands to full-screen when an app *right-click menu* is
open (=win.ctxGroup=), so that menu (a =Loader= floating below the pill) is
clickable and an outside click dismisses it.

** Open windows / taskbar (winbridge.py)
KWin advertises no window-list protocol and no active-window over DBus, so
=winbridge.py= (run as =python <shellDir>/winbridge.py=) glues two KDE APIs and
prints one JSON line =\{active, windows\}= per update on stdout, which a =Process= +
=SplitParser= parses into =root.windows= / =root.activeWindow=:
- *window list*: the KRunner "windows" runner =org.kde.KWin /WindowsRunner=,
  =org.kde.krunner1.Match("")= returns every window =(id, title, icon, …)= (icon is
  already an app-icon name like =org.kde.dolphin=); polled ~1 s, deduped by id
  (the runner returns each window twice). =Run(id, "")= focuses one.
- *active window*: the helper owns DBus name =org.kde.pill= and loads a small KWin
  script (via =/Scripting=) that calls us on =workspace.windowActivated= with
  =String(window.internalId)= (=\{uuid\}=, matching the krunner ids) plus the
  window's =fullScreen= flag; it also re-pushes when the active window's
  =fullScreenChanged= fires (so going fullscreen in place hides the pill). The flag
  rides the JSON line as =fullscreen= and drives =win.fsHide=. Unloaded on exit.

In the UI, =root.appGroups= groups windows by =icon= (one tile per app, with a
count badge for ≥2 windows and an underline that turns accent when any of the
app's windows is active). Left-click =cycleGroup= focuses the app's next window;
right-click opens a floating menu (this app's windows to focus + launcher actions
from =DesktopEntries.heuristicLookup(icon).actions= when available).

** Virtual desktops (init.qml, DBus)
Three =Process= blocks drive =gdbus= against =org.kde.KWin /VirtualDesktopManager=:
fetch the =desktops= list (a regex parses =(uint32 N, 'id', 'name')= tuples — the
=uint32= tag is optional because gdbus only prints it on the first tuple), fetch
=current=, and =gdbus monitor= the =currentChanged= signal so the dots stay live.
=switchDesktop(id)= sets the writable =current= property.

** Menus (one file each)
- =NetworkMenu=: finds the Wi-Fi =NetworkDevice= (=type === DeviceType.Wifi=),
  lists =device.networks= sorted active-first then by =signalStrength=, shows
  signal bars + a lock for secured nets, connect/disconnect, and a password
  overlay calling =connectWithPsk()= for secured unknown nets. Toggles
  =Networking.wifiEnabled=. Turns the scanner on while visible.
- =VolumeMenu=: a =PwObjectTracker= over every node keeps audio live. Nodes are
  classified by =properties["media.class"]=: =Audio/Sink= (speakers),
  =Audio/Source= (mics), =Stream/Output/Audio= (apps). Per row: name, set-default
  marker (=preferredDefaultAudioSink/Source=), mute, and a =PillSlider= bound to
  =node.audio.volume=.
- =BluetoothMenu=: adapter power + scan toggles (=defaultAdapter.enabled= /
  =.discovering=), then three filtered sections — Connected, Paired, Available —
  each row connect/disconnect/pair via the device methods, with battery % when
  =batteryAvailable=.
- =BatteryMenu=: =UPower.devices= filtered to present, non-line-power devices,
  each with =IconImage { source: Quickshell.iconPath(iconName) }=, name/type,
  state and percentage.

Every menu declares a =signal closeRequested()= and opens with a =MenuHeader=
(back chevron + title + trailing toggle slot); the chevron emits =closeRequested=,
which =init.qml='s =Connections= on the menu loader turns into =win.open = false=.

** Launcher (init.qml + Launcher.qml)
=init.qml= builds =appList= once (=DesktopEntries.applications=, =noDisplay=
filtered, name-sorted) at the long-lived root and shares it with every monitor's
=Launcher=, so opening is instant and survives close. Grid mode + favourite app
ids persist in =Quickshell.stateDir + "/launcher.json"= via a =FileView= +
=JsonAdapter= (=settings=); the adapter auto-flushes on change and is created on
first run (=onLoadFailed → writeAdapter()=). The =Launcher= itself: a *back chevron*
(closes the launcher) left of a focused search field (matches
name/genericName/keywords), a grid/list toggle, ★ favourites (empty query shows
favourites if any, else all apps; searching is always a flat list), a right-click
menu (=DesktopEntry.actions= + favourite toggle), and a calculator (a safe
arithmetic expression, or one prefixed with ===, shows a result row that
=wl-copy='s on click/Enter). A small *power row* sits bottom-right —
lock/logout/reboot/shutdown (16px), wired to =loginctl lock-session= and
=org.kde.Shutdown='s =logout=/=logoutAndReboot=/=logoutAndShutdown= over =gdbus=.
=init.qml= focuses + clears the field on each open via a =Connections= on
=win.launcher=.

** Notifications (Notifications.qml + NotificationView.qml + NotificationStack.qml + NotificationHistory.qml)
=init.qml= instantiates one =Notifications= object (=notifs=) at the long-lived
root and shares it with every monitor. It owns a =NotificationServer= that
advertises body/markup/images/actions/action-icons/inline-reply/persistence, so
apps send the rich payload. Every notification is kept =tracked= so it survives as
*history* in =server.trackedNotifications=; =notifs.grouped= buckets that by app
(newest-first inside a group, group ordered by its newest item) for the history
pane. A separate =active= stack (newest first) holds the *un-closed popups*. Each
notification has its *own* countdown (so several popups expire independently),
held centrally in =remaining= keyed by id (a single =Timer= steps them and a
=tick= counter refreshes the bars) — *not* per-card, since the deck's Repeater
recreates its delegates whenever =active= changes. *Timeout policy* (=timeoutFor=):
every popup fades in *5s* (=defaultTimeoutMs=) — the app's requested timeout is
*ignored* (apps tend to ask for ~60s) — *except* genuinely permanent ones
(=expireTimeout === 0=) or =Critical=, which never auto-expire. =hold(true)= — set
while the deck is hovered — pauses *and resets every* countdown at once. Closing a
popup (the X) or letting it time out only removes it from =active= and *always
keeps* it in history (even transient ones); we deliberately avoid
=Notification.dismiss()/expire()= because in Quickshell those *destroy* the
notification (so they'd wipe the history copy too) — the trade-off is the sender
isn't told the popup closed. Only =forget()= (the X *in history*) / =clearAll()=
remove from history (=tracked = false=). The spec carries no timestamp, so arrival
time is stamped on receipt (re-stamped to "now" for =lastGeneration= notifications
restored on reload).

A =NotificationView= card is two columns: the notification *image* (200px wide,
aspect kept) or the *app icon* on the left; on the right three rows — summary +
close-X with a vertical countdown bar, body (=StyledText=, links open
externally), and relative time + action buttons — plus an inline-reply field when
the notification supports it (Telegram, KDE Connect: Enter → =sendInlineReply()=).
The image is resolved robustly (=resolveImage()=): an =image-path= hint is loaded
as a =file://= URL directly (Flameshot & co. send the screenshot that way, and
Quickshell would otherwise route a bare path through its *icon* provider and drop
it), otherwise Quickshell's =image= (the =image-data= provider URL) is used. The
=Image= loads *synchronously* (=asynchronous: false=) — Quickshell's image-data
provider serves nothing on the async path. The
same card is reused three ways: in the deck (=autoExpire:true=), as *history* rows
(=inHistory:true=, so the X forgets instead of dismissing), and elsewhere.

=NotificationStack= lays the =active= cards out as a *deck*: at rest the newest is
on top and the rest peek out below it (offset + scaled back, capped at
=maxDeck=); hovering the stack drops them into a full vertical list and sets
=notifs.held=. Its =implicitHeight= reports the laid-out height (deck vs expanded),
recomputed reactively via a =relayout= bump on any card's height change. Once
there's an actual stack (more than one active popup) a floating *"Dismiss all"*
pill appears in a reserved =headroom= band at the deck's top-right; clicking it
calls =notifs.dismissAll()=, which closes every popup at once but keeps them in
history (exactly like dismissing each card's X).

In =init.qml= the collapsed pill *morphs* into this deck whenever a notification is
active and the pill isn't clicked-open / launcher / app-menu (=win.notifMorph=):
the clock and dashboard rows hide, the pill's own background is dropped, and
=pill.height= tracks the deck's =implicitHeight= (so hovering grows the pill as the
deck expands) — you close every notification (or let them time out) to return to
the clock. While the pill *is* clicked-open / launcher / showing an app menu, the
same deck floats *below* the pill instead (both via a =Loader= over the shared
=cStack= component, so only the visible one runs timers). A morphing notification
*never* takes keyboard focus (the surface only grabs focus while =open=/=launcher=),
so it can't steal focus from the active window — inline reply is typed from the
floating cards under an *opened* pill. The Row-2 notification status icon opens
=NotificationHistory= (menu 4).

** Look, translucency & icons
The palette in =Theme.qml= is the warm vermillion/cream scheme borrowed from
Ricelin (=accent= vermillion over a cocoa-black =bg=). At rest (collapsed and
un-hovered) the pill is a *borderless translucent gradient* (=theme.bgGradTop= →
=theme.bgGradBottom=) and slightly *dimmed* (=theme.idleOpacity=), and its clock
text is itself a touch translucent so a hint of the backdrop shows through; it
animates to a solid, full-opacity bordered surface the moment it is hovered,
opened, or a notification morphs it. This is alpha translucency only — true
backdrop *blur* would need the KWin blur protocol, which Quickshell does not
expose (no blur type in its qmltypes).

Icons resolve through Qt's icon theme. =run-pill.sh= loads the *KDE* Qt platform
theme (=QT_QPA_PLATFORMTHEME=kde=) so every icon — the launcher app list, status
glyphs, tray — follows KDE's configured icon theme (System Settings ▸ Icons). To
force a specific theme regardless of KDE, set =Theme.qml='s =iconTheme: "Name"=
(e.g. ="Papirus"=); =run-pill.sh= reads it and applies it via the gtk3 platform
theme (Qt has no env var for an icon-theme name, so we write a private
=gtk-3.0/settings.ini= and prefix =XDG_CONFIG_HOME=). =""= follows KDE.

** Reusable widgets
=PillToggle= (themed switch), =PillSlider= (themed 0..1 slider) and =MenuHeader=
(back chevron + title + trailing slot) keep the menus small and the look coherent.

#+begin_src qml :tangle ~/.config/quickshell/pill/PillToggle.qml :mkdirp yes
pragma ComponentBehavior: Bound
// PillToggle.qml — a small themed on/off switch. Reusable across menus.
import QtQuick

Item {
    id: root
    required property var theme
    property bool checked: false
    signal toggled(bool value)

    implicitWidth: 34
    implicitHeight: 18

    Rectangle {
        anchors.fill: parent

pragma ComponentBehavior: Bound
// Notifications.qml — the freedesktop notification server + popup/history state.
// Instantiated once in init.qml as `Notifications { id: notifs; theme: theme }`
// and shared with every monitor's views (no singletons). It:
//   * owns a NotificationServer advertising body/markup/images/actions/action-
//     icons/inline-reply/persistence, so apps send us the rich payload;
//   * keeps every notification `tracked` so it survives as *history*
//     (server.trackedNotifications), grouped by app in the history view;
//   * maintains an `active` stack (newest first) of un-closed popups that drive
//     the collapsed-pill morph; each notification has its own countdown (kept in
//     `remaining`, keyed by id), and `held` (set while a deck is hovered) pauses
//     and resets them all. Closing a popup or letting it time out only removes it
//     from `active` and keeps the (tracked) history copy — we never call
//     Notification.dismiss()/expire(), which would *destroy* it. Forget/clear set
//     tracked=false to actually drop a notification from history.
//
// The spec carries no timestamp, so we stamp arrival time ourselves (`stamps`);
// on a Quickshell reload restored notifications are re-stamped to "now".
import QtQuick
import QtQml
import Quickshell
import Quickshell.Services.Notifications

QtObject {
    id: root
    required property var theme

    // ---- the server: the capabilities we advertise to apps ----
    readonly property NotificationServer server: NotificationServer {
        keepOnReload: true
        persistenceSupported: true
        bodySupported: true
        bodyMarkupSupported: true
        bodyImagesSupported: true
        imageSupported: true
        actionsSupported: true
        actionIconsSupported: true
        inlineReplySupported: true
        onNotification: n => root.onArrived(n)
    }

    // ---- arrival timestamps (id -> ms since epoch); the spec carries none ----
    property var stamps: ({})

    // ---- active popup stack (newest first) drives the pill morph ----
    // Per-notification countdowns live HERE (keyed by id), not in the cards: the
    // deck's Repeater recreates its delegates whenever `active` changes, which
    // would otherwise reset every timer on each arrival. `held` (set while a deck
    // is hovered) pauses every countdown and resets them all to full.
    property var active: []
    readonly property var current: active.length ? active[0] : null   // newest
    property bool held: false
    property var remaining: ({})              // id -> ms left
    property int tick: 0                       // bumped each step to refresh progress bindings
    readonly property bool anyReply: {
        for (const n of active) if (n && n.hasInlineReply) return true;
        return false;
    }

    function progressFor(n) {
        root.tick;                            // dependency: re-eval each countdown step
        if (!n) return 0;
        const t = root.timeoutFor(n);
        if (t <= 0) return 0;
        const r = root.remaining[n.id];
        return r === undefined ? 1 : Math.max(0, Math.min(1, r / t));
    }

    readonly property Timer ticker: Timer {
        interval: 50; repeat: true
        running: root.active.length > 0 && !root.held
        onTriggered: {
            const dead = [];
            for (const n of root.active) {
                const t = root.timeoutFor(n);
                if (t <= 0) continue;          // never-expire (Critical / app asked 0)
                let r = root.remaining[n.id];
                r = (r === undefined ? t : r) - interval;
                root.remaining[n.id] = r;
                if (r <= 0) dead.push(n);
            }
            root.tick++;                       // refresh progress bars
            for (const n of dead) root.expireOne(n);
        }
    }

    // a 1-second clock so "x min ago" stays fresh in the cards / history
    readonly property var clock: SystemClock { precision: SystemClock.Seconds }
    readonly property double nowMs: clock.date.getTime()

    function onArrived(n) {
        if (!root.stamps[n.id])
            root.stamps[n.id] = (new Date()).getTime();
        n.tracked = true;                     // keep it for history
        if (n.lastGeneration)                 // restored on reload: history only, don't re-pop
            return;
        // de-dupe (apps reuse ids to replace): drop any copy, push to the front
        const a = root.active.filter(x => x.id !== n.id);
        a.unshift(n);
        root.active = a;
        root.remaining[n.id] = root.timeoutFor(n);   // start (or restart) its countdown
        root.tick++;
    }

    readonly property int defaultTimeoutMs: 5000   // every non-permanent notification fades in 5s
    function timeoutFor(n) {
        if (!n) return 0;
        // permanent: the app explicitly asked never to expire (0), or it's Critical
        if (n.expireTimeout === 0 || n.urgency === NotificationUrgency.Critical) return 0;
        // everything else: ignore the app's value (often ~60s) and use 5s
        return root.defaultTimeoutMs;
    }

    // remove from the active stack only (the history copy is untouched)
    function drop(n) {
        if (!n) return;
        root.active = root.active.filter(x => x.id !== n.id);
        delete root.remaining[n.id];
    }
    // close a popup: stop showing it but ALWAYS KEEP it in history (even the X and
    // even transient notifications — only `forget`/`clearAll` remove from history).
    // We deliberately do NOT call Notification.dismiss()/expire() here — in
    // Quickshell those *destroy* the notification (untracking it), which would wipe
    // the history copy too; the trade-off is the sending app isn't told it closed.
    function closePopup(n) {
        if (!n) return;
        root.drop(n);   // remove from the popup stack; the tracked history copy stays
    }
    function dismiss(n)   { root.closePopup(n); }   // X on a popup
    function expireOne(n) { root.closePopup(n); }   // a countdown elapsed
    // dismiss the whole active popup deck at once (history is kept, like the X)
    function dismissAll() { for (const n of root.active.slice()) root.closePopup(n); }
    function hold(v) {                                // hover: pause + reset every countdown
        root.held = v;
        if (v) {
            for (const n of root.active) root.remaining[n.id] = root.timeoutFor(n);
            root.tick++;
        }
    }

    // remove from history entirely (tracked=false == dismiss(): destroys it).
    // Rebuild *now* rather than waiting for trackedNotificationsChanged: the dying
    // notification can linger in `values` for a cycle with its content already
    // cleared, which would flash an empty card in the history (rebuild filters it).
    function forget(n) { if (n) { root.drop(n); n.tracked = false; root.rebuild(); } }
    function clearAll() {
        const all = root.server.trackedNotifications ? root.server.trackedNotifications.values.slice() : [];
        for (const n of all) n.tracked = false;
        root.active = [];
        root.rebuild();
    }

    // ---- watch each tracked notification's `closed` (e.g. the sender closed or
    //      replaced it) so it leaves the active stack too ----
    readonly property Instantiator watcher: Instantiator {
        model: root.server.trackedNotifications
        delegate: Connections {
            required property var modelData
            target: modelData
            function onClosed(reason) { root.drop(modelData); }
        }
    }

    // ---- grouped history: by app, newest-first within a group, group ordered by
    //      its newest item, so a fresh notification floats its app to the top ----
    property var grouped: []
    function rebuild() {
        const list = root.server.trackedNotifications ? root.server.trackedNotifications.values : [];
        const ts = id => root.stamps[id] || 0;
        const by = {}, order = [];
        for (const n of list) {
            // a just-forgotten notification can still appear in `values` for one
            // cycle (emptied of content) while it is being destroyed — skip it so
            // history never shows a contentless card.
            if (!n || !n.tracked) continue;
            const k = n.appName || "Unknown";
            if (!by[k]) { by[k] = { app: k, items: [] }; order.push(k); }
            by[k].items.push(n);
        }
        for (const k of order) by[k].items.sort((x, y) => ts(y.id) - ts(x.id));
        const gs = order.map(k => by[k]);
        gs.sort((g1, g2) => ts(g2.items[0].id) - ts(g1.items[0].id));
        root.grouped = gs;
    }
    readonly property Connections rebuilder: Connections {
        target: root.server
        function onTrackedNotificationsChanged() { root.rebuild(); }
    }
    Component.onCompleted: root.rebuild()

    function relTime(id) {
        const t = root.stamps[id]; if (!t) return "";
        let s = Math.floor((root.nowMs - t) / 1000); if (s < 0) s = 0;
        if (s < 60) return "now";
        const m = Math.floor(s / 60); if (m < 60) return m + "m ago";
        const h = Math.floor(m / 60); if (h < 24) return h + "h ago";
        return Math.floor(h / 24) + "d ago";
    }
}

def windows():
    try:
        res = bus.call_sync(
            "org.kde.KWin",
            "/WindowsRunner",
            "org.kde.krunner1",
            "Match",
            GLib.Variant("(s)", ("",)),
            GLib.VariantType("(a(sssida{sv}))"),
            Gio.DBusCallFlags.NONE,
            3000,
            None,
        )
    except Exception:
        return []
    tb = state["taskbar"]
    seen = {}
    for m in res.unpack()[0]:
        mid, text, icon = m[0], m[1], m[2]  # id, title, icon name
        if not mid.startswith("0_") or mid in seen:
            continue
        uuid = mid[2:]
        # once KWin has reported the eligible set, drop skip-taskbar windows;
        # before the first report, show everything (previous behaviour)
        if tb is not None and uuid not in tb:
            continue
        seen[mid] = {"id": mid, "uuid": uuid, "title": text, "icon": icon}
    return sorted(seen.values(), key=lambda d: d["id"])

#+begin_src sh :tangle ~/.config/quickshell/pill/run-pill.sh :mkdirp yes :tangle-mode (identity #o755)
#!/bin/sh
# run-pill.sh — launch the pill with a Wayland environment resolved at runtime.
#
# After a reboot the login shell often has no WAYLAND_DISPLAY / QT_QPA_PLATFORM
# exported, so Qt falls back to the xcb plugin, fails to connect, and crashes.
# Qt selects its platform plugin before any QML is parsed, so this has to be
# fixed in the launcher rather than in init.qml. We discover the compositor's
# socket from XDG_RUNTIME_DIR and point Qt at it.
#
# Usage:  ./run-pill.sh            (runs quickshell/init.qml next to this script)
#         ./run-pill.sh <args>     (extra args are forwarded to qs)

set -eu

dir=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)

# XDG_RUNTIME_DIR is where the wayland socket lives; derive it if absent.
: "${XDG_RUNTIME_DIR:=/run/user/$(id -u)}"
export XDG_RUNTIME_DIR

# If we weren't handed a display, find the compositor's socket.
# Prefer wayland-0, else the first wayland-N socket present.
if [ -z "${WAYLAND_DISPLAY:-}" ]; then
    if [ -S "$XDG_RUNTIME_DIR/wayland-0" ]; then
        WAYLAND_DISPLAY=wayland-0
    else
        for sock in "$XDG_RUNTIME_DIR"/wayland-*; do
            case "$sock" in
                *.lock) continue ;;
            esac
            [ -S "$sock" ] || continue
            WAYLAND_DISPLAY=$(basename "$sock")
            break
        done
    fi
fi

if [ -z "${WAYLAND_DISPLAY:-}" ]; then
    echo "run-pill.sh: no wayland socket found in $XDG_RUNTIME_DIR" >&2
    exit 1
fi
export WAYLAND_DISPLAY
export QT_QPA_PLATFORM=wayland

# Icon theme. Icons (launcher app list, status/tray glyphs) resolve through Qt's
# icon theme. By default we load the KDE Qt platform theme so they follow KDE's
# configured icon theme (System Settings -> Icons). If Theme.qml sets
# `iconTheme: "Name"`, force that instead via the gtk3 platform theme, which reads
# an icon-theme name from a settings.ini we own (Qt has no env var for it). This
# keeps the override self-contained (XDG_CONFIG_HOME is prefixed, not replaced).
icon_theme=$(sed -n 's/.*property[[:space:]][[:space:]]*string[[:space:]][[:space:]]*iconTheme:[[:space:]]*"\([^"]*\)".*/\1/p' "$dir/Theme.qml" 2>/dev/null | head -n1)
if [ -n "${icon_theme:-}" ]; then
    cfg="${XDG_STATE_HOME:-$HOME/.local/state}/quickshell-pill"
    mkdir -p "$cfg/gtk-3.0"
    printf '[Settings]\ngtk-icon-theme-name=%s\n' "$icon_theme" > "$cfg/gtk-3.0/settings.ini"
    export XDG_CONFIG_HOME="$cfg:${XDG_CONFIG_HOME:-$HOME/.config}"
    export QT_QPA_PLATFORMTHEME=gtk3
else
    export QT_QPA_PLATFORMTHEME=kde
fi

exec qs -p "$dir/init.qml" "$@"
#+end_src

* Tangling (how to regenerate the =.qml= files)

This file owns the code; the =.qml= files *and* =winbridge.py= are *generated*.
=C-c C-v t= (=org-babel-tangle=) tangles *all* blocks at once to their =:tangle=
targets in this directory. (Editing a generated file directly is lost on the next
tangle — change it here instead.) Note: launching the pill makes =winbridge.py=
load a small KWin script (=quickshell-pill-active=); it is unloaded when the
bridge exits. After editing any block:

- In Emacs with this file open: =C-c C-v t=.
- Or batch / shell:
  =emacs --batch -l org -eval '(org-babel-tangle-file "quickshell/qs-pill-docs.org")'=

Then validate:  =qs -p quickshell/init.qml=  (Ctrl-C to stop). A clean load prints
"Configuration Loaded" with no WARN lines.
