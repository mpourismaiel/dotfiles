This file is the *design documentation* for the Quickshell "pill". The code
itself lives as plain files in [[file:pill/][=pill/=]] (this repo) — edit those directly, then
run [[file:pill/deploy.sh][=pill/deploy.sh=]] to validate and copy them to the live config at
=~/.config/quickshell/pill/=. (This file used to be a literate org that tangled
the code; the blocks were broken out into =pill/= in Aug 2026. There is no
tangling any more — nothing here generates code.) Each file's section below
explains what it does and *why* — read it before touching the matching source
file, and keep the prose in sync when behaviour changes; they are a pair.

* What this is

A Quickshell replacement for KDE's panels: a single *pill* at the top-center of
every monitor, always on top, reserving no screen space, hidden only while a
fullscreen window is focused. It morphs through four stages — a collapsed clock, a
hovered dashboard (virtual-desktop dots, grouped open apps, status icons, system
tray, date/time), a clicked-open *control panel* (network / volume / bluetooth /
battery / clipboard-history / notification-history menus), and an app *launcher*. It is also this
machine's freedesktop *notification daemon* (popups morph the pill; history +
inline reply), and flashes transient *action bursts* on desktop switches and
keyboard-layout changes. Clicking outside only collapses it — the click is not
passed through.

Where KWin exposes no client-visible protocol (window list, active window) the
pill leans on KDE/system APIs over DBus rather than rolling its own — see
[[*Environment (verified, not assumed)][§ Environment]]. Palette and animation
cues are borrowed from [[https://github.com/Gakuseei/Ricelin][Gakuseei/Ricelin]]
(Hyprland-only; its workspace/taskbar code does not port to KWin).

* Environment (verified, not assumed)

| Thing               | Value                                            |
|---------------------+--------------------------------------------------|
| Quickshell          | 0.3.0 (Arch), binary =qs= / =quickshell=         |
| Qt                  | 6.11                                             |
| Desktop             | KDE Plasma 6.7.1, KWin, Wayland                   |
| Audio / Power       | Pipewire, UPower — active                         |
| Network / Bluetooth | NetworkManager 1.56, BlueZ — active               |

*Critical compositor fact* (=wayland-info=): KWin advertises =zwlr_layer_shell_v1=
and =org_kde_plasma_virtual_desktop_management=, but NOT =ext_workspace_v1=,
=zwlr_foreign_toplevel_manager_v1=, or =org_kde_plasma_window_management=. So
Quickshell's =WindowManager= and =Wayland.ToplevelManager= exist but *don't
function* here — virtual desktops go through KWin DBus, and the taskbar /
fullscreen-hide are blocked on there being no client-visible window-list protocol.

* Taking over notifications from Plasma

The pill is a real freedesktop notification daemon (=NotificationServer=, see
[[*Notifications.qml][§ Notifications.qml]]). Only one process may own the bus
name =org.freedesktop.Notifications=, and on this machine that owner is
*plasmashell itself* (the =org.kde.plasma.notifications= tray applet) — registered
*without* =ALLOW_REPLACEMENT=, so the pill cannot grab it at runtime. Plasma must
be stopped from registering it first:

1. System tray ▸ *Configure System Tray…* ▸ *Entries* ▸ set *Notifications* to
   *Disabled* (not "Hidden" — that still loads the applet and grabs the name).
2. Restart the shell: =systemctl --user restart plasma-plasmashell= (or re-login).
3. Start the pill (=./run-pill.sh=); confirm it owns the daemon — =busctl --user
   call org.freedesktop.Notifications /org/freedesktop/Notifications
   org.freedesktop.Notifications GetServerInformation= should report ="quickshell"=.

To hand notifications back, re-enable the tray entry and restart plasmashell.

** Theme.qml
*** Description
All colours, metrics, timings and font/icon settings in one place — restyle the
whole pill here. Instantiated once in =init.qml= as =Theme { id: theme }= and
passed into every component as a =theme= property (no singletons).

The palette is the *Broadsheet* scheme (see =__ignore__/Broadsheet.html=): a warm
vermillion =accent= over a cocoa-black =bg=, cream text, set in *DM Serif Display*
(titles/clock/figures), *IBM Plex Sans* (body) and *IBM Plex Mono* (uppercase
labels), with chrome glyphs from *Material Symbols Rounded* (=icon=, rendered via
[[*MSym.qml][=MSym=]]) while app/tray icons stay Qt-themed. At rest the pill is a borderless translucent
gradient (=bgGradTop= → =bgGradBottom=) and slightly dimmed (=idleOpacity=); it
animates to a solid bordered surface the moment it is hovered, opened, or morphed
by a notification. This is alpha translucency only — true backdrop *blur* would
need the KWin blur protocol, which Quickshell does not expose. Icons resolve
through Qt's icon theme; =iconTheme= forces a specific one (e.g. ="Papirus"=), =""=
follows KDE — =run-pill.sh= reads this and applies it (see [[*run-pill.sh][§ run-pill.sh]]).

*Colours are user-customisable at runtime* (Settings → Appearance). Every colour
property now resolves through an =overrides= map (=theme.overrides=, bound in
=init.qml= to the persisted =theme.json= adapter): a present, non-blank entry for
that key wins, otherwise the shipped value in =defaults= (a =key → css-string=
map) is used. So the built-in palette lives in =defaults=, the user's edits live
in =theme.json=, and every widget still just reads =theme.<key>=. Supporting
machinery: =palette= (ordered =[{group,key,label}]= list the Appearance page
renders), =presets= (one-click starting points; =Default= is the empty override
map), and two colour helpers used across the theme editor — =parseColor(str)=
(any css colour → Qt colour: =#rgb/#rgba/#rrggbb/#rrggbbaa=, =rgb()/rgba()=,
=hsl()/hsla()= with comma/space/slash separators + optional =%=, or a named
colour) and =formatColor(col, unit)= (Qt colour → css string in =hex= / =rgb= /
=hsl=, alpha only when < 1). See [[*AppearanceSettings.qml][=AppearanceSettings=]].

** MSym.qml
*** Description
A single *Material Symbols Rounded* glyph. =icon= is the symbol's ligature name
(e.g. ="chevron_left"=, ="search"=, ="grid_view"=); =fill= / =weight= / =grade= /
=opticalSize= map to the font's variable axes (=FILL=/=wght=/=GRAD=/=opsz=), so a
=fill: 1= icon is the solid variant. Used for every chrome glyph (menu/launcher/
search/chevron/status icons); *app and tray icons stay Qt-themed* (=IconImage= /
=Quickshell.iconPath=). Sizing is via =size= (sets both the pixel size and =opsz=).

** PillSurface.qml
*** Description
The *expanded* pill's background as a =Shape= (not a plain rounded =Rectangle=), so
the dashboard / open panel can sit *flush against the screen's top edge* with
*"rounded out" corners*: the free (bottom) corners are convex, while the two corners at
the top edge are *concave wings* that flare outward into the edge (the caelestia look).
Only the *expanded* states use this — the resting/collapsed pill stays the floating
rounded =Rectangle=; =init.qml= cross-fades between the two. =radius= is the convex
free-edge corner, =wing= the concave edge flare; both animate. Borderless by default
(pass a =strokeColor=/=strokeWidth= only if a hairline is wanted). Mirrors emaqs's
=PillSurface= but attaches to the *top* edge instead of the bottom.

** MenuHeader.qml
*** Description

stepper arrows are tagged too.

** MenuKbNav.qml
*** Description
The keyboard-navigation overlay for the control-panel menus, hosted by =init.qml=
over the menu loader and active only in *keyboard-nav mode* (=win.kbNav=, entered
via the =expand= IPC — see [[*init.qml][§ init.qml]]). It scans the loaded menu's
visual tree for items tagged =kbFocusable: true= (the =MenuHeader= back button —
tagged =kbDefault= so it's every menu's initial focus — the header nav arrows,
=PillToggle=, an interactive =ConnButton=, and each menu's own rows/tabs/chips),
then:

- *Arrows* move spatially: the nearest focusable in the pressed direction wins,
  with the orthogonal offset weighted 3× so rows stay rows and the volume menu's
  tab bar naturally becomes a left/right strip.
- *Enter* calls the focused item's =keyClick()= (each tag carries one, mirroring
  its =MouseArea='s click handler).
- *Escape* emits =escaped()= (init returns to the expanded dashboard).
- *Letter shortcuts* (=shortcuts: true=, calendar menu only): f/c/n/w/v/b emit
  =shortcutRequested(menu)= — the same first-level menu jumps the dashboard offers.
- *Hover overrides focus*: a =HoverHandler= hit-tests the focusable list on every
  pointer move, so whatever the mouse touches becomes the keyboard focus. The
  hit-test is *clip-aware* (=visRectOf= intersects each item with its clipping
  ancestors), so a row scrolled out of a Flickable can't catch the pointer near
  the pill's edge — only the arrows reach hidden rows, and those scroll them
  into view (=ensureVisible= walks up to the nearest Flickable).

Focus is shown as *hover*: every tagged item declares =property bool kbFocused=
(MenuKbNav sets it as focus moves) and styles itself exactly the way its own
hover / the clipboard rows do — rows and chips fill =rowHi=, faint labels and
icons brighten to =text=, a =PillToggle= gets a bright track border, the search
field its accent border. Opaque =bgHover= behind translucent styling (a toggle's
track, faint caps) *washes the control out*, which is why the items self-style
rather than relying on a drawn square. A =bgHover= floating square (the
dashboard's roving-hover look, drawn *under* the menu content — the overlay
sits at =z: -1=) remains only as a fallback for any future =kbFocusable= tag
without a =kbFocused= property; it re-maps a few times a second (=tick=) so it
tracks scrolling Flickables. If a =pillKbInput= field (search, wifi password) takes the keys and
later lets go, an active-focus watcher reclaims them (active focus lands on a
focus scope, and the =focus:= binding alone never re-fires). Items inside an
invisible subtree (a hidden tab, a collapsed section) are never collected, so
the scan follows what's on screen. The calendar's month grid is deliberately
*not* tagged — it keeps mouse-only interaction for now.

** SearchField.qml
*** Description
The compact search row shared by the network / bluetooth / volume menus, styled
after the clipboard menu's search strip (icon + inline =TextInput=). It does *not*
auto-focus: clicking it (or, in keyboard-nav mode, arrowing to it and pressing
Enter — it's =kbFocusable=, =keyClick()= focuses the input) pulls the keyboard via
the usual =pillKbInput= mechanism, so browsing the menu never grabs. *Escape*
clears the query and drops focus — in keyboard-nav mode [[*MenuKbNav.qml][=MenuKbNav=]]
reclaims the keys (its active-focus watcher), otherwise the pill releases the
keyboard. A trailing ✕ appears while a query is set. The owning menu reads =text=
and filters its sections with it, keeping each section label / divider only while
the section still has matches.

** Brightness.qml
*** Description
Per-display screen brightness over KDE's =org.kde.ScreenBrightness= DBus service —
the exact backend Plasma's own brightness slider and keys use, so it drives the
internal panel's *backlight* and external monitors over *DDC/CI* alike (no
=ddcutil=/=brightnessctl= of our own). Owned once in =init.qml= and shared with the
[[*BatteryMenu.qml][battery menu]] (a slider per display) and the *brightness
shortcut* (=stepActive=, which adjusts whichever monitor is active). Displays are
enumerated on demand (=refresh()=, called when the battery menu opens): for each
=DisplaysDBusNames= entry it reads =Label=, =Brightness=, =MaxBrightness= and
=IsInternal=. Slider writes are *optimistic* (the UI moves at once) and *throttled*
(≈80 ms, with a guaranteed trailing write) so a drag doesn't spawn a =qdbus= process
per pixel or thrash a slow DDC bus. =stepActive(screen, sign)= re-reads the live
value in-shell before clamping + writing, so a keybind never drifts from KDE's OSD.
Mirrors =NetState= / =Clipboard= (no singletons).

** CalendarMenu.qml
*** Description
The calendar pane (=win.menu === 6=), opened by clicking the dashboard date/time
(not from the status row). A basic 7-row month grid — weekday-name column headers,
ISO week numbers down the left rail, and the trailing/leading days of the
adjacent months filling the first and last rows — with the month name as the
=MenuHeader= title, a =← →= stepper right after it to page months, and a *Today*
button in the header's trailing slot next to a *Gregorian ⇄ Shamsi* toggle.
Clicking a leading/trailing day (one from an adjacent month) pages to that month
and selects it. Gregorian is primary (the big figure); the Jalaali
(Shamsi) day sits under it as dim subtext, matching Plasma's calendar. Flipping the
toggle swaps which calendar drives the grid (month, weekday order — Sunday-start for
Gregorian, Saturday-start for Shamsi — and the figures), the other becoming the
subtext.

Today is selected on open. Two *detached* roving squares sit behind the cells and
slide between them exactly like the dashboard's shared hover square: a faded-gray
=bgHover= square follows the pointer, and the launcher-hover =accentSoft= square marks
the selection. Changing month plays a quick slide-and-fade. The right panel shows the
selected day in both calendars (=Saturday, July 5th, 2026= over =14 Tir 1405=) and its
*Org agenda* — TODO entries first, then everything else — pulled from the running
Emacs daemon via [[*OrgAgenda.qml][=OrgAgenda=]]; days that have any agenda entry get a
dot. A =+= button opposite the *Org agenda* title opens the agenda in Emacs (reusing an
existing frame). Jalaali conversion is the compact =jalaali-js= algorithm, inlined.

Finance rides along (via [[*FinanceState.qml][=FinanceState=]]): days with journal
entries grow a second, *green* dot next to the agenda dot, the selected day's
transactions are listed under the agenda (description + signed amount), and a
wallet button in the header switches to the [[*FinanceMenu.qml][finance menu]]
(=financeRequested()=). Days carrying a *forecast* (periodic-rule) occurrence show
a hollow gold ring, and the selected day's forecasts are listed under the real
transactions in an *Upcoming* section — each with a gold checkbox that hands the
row (=confirmForecast=, via =FinanceState.pendingPrefill=) to the finance menu's
add form, prefilled with the date/amount/currency/category/account so the user can
confirm or adjust it into a real transaction. All finance signals hide while
privacy is on. The *org agenda* honours the same toggle (=showOrg=): its grid dots,
the "Org agenda" heading, the day list and the empty-state line all disappear while
finance privacy / DND is on, alongside the finance and Google-calendar sections.

** OrgAgenda.qml
*** Description
Org-agenda *state*, instantiated once in =init.qml= as =OrgAgenda { id: orgAgenda }=
and handed to [[*CalendarMenu.qml][=CalendarMenu=]] (no singletons, mirroring
=Clipboard= / =Notifications=). It shells out to [[*orgbridge.py][=orgbridge.py=]],
which talks to the running Emacs daemon over =emacsclient=: =loadDay(key)= fills
=dayItems= (the =\{text, todo, type\}= entries for a =YYYY-MM-DD=), =loadRange(a, b)=
fills =rangeDays= (the set of dates in =[a,b]= that have any entry — drives the
calendar dots, queried once per shown month grid), and =openAgenda(key)= opens the Org
agenda in Emacs (reusing an existing frame). All are best-effort: if Emacs isn't
reachable the parses fall back to empty, so the calendar still works.

*Feature gate.* =enabled= (bound to =settings.orgAgendaEnabled=, off by default) short-
circuits every load to a no-op + empty model and stops the poll timers, so with the
feature off there are no =orgbridge= calls and no dots/deadlines. =agendaDir= (bound to
=settings.orgAgendaDir=) is passed to =orgbridge= as =--dir= and rebinds
=org-agenda-files= for the query, so the pill isn't tied to one machine's Emacs config.
See [[*SettingsMenu.qml + FeaturePage.qml][=SettingsMenu=]].

The loaded day + range are re-pulled on their own: =loadRange= remembers its bounds
(=rangeA=/=rangeB=), =refresh()= re-runs =loadDay(dayKey)= and =loadRange(rangeA, rangeB)=,
and a 10-minute =agendaPoll= =Timer= calls it so entries added in Emacs surface without
reopening the calendar (bindings on =dayItems=/=rangeDays= update the open menu reactively).

It also drives the *deadline watch* behind the collapsed pill's under-line and the
[[*AgendaMenu.qml][=AgendaMenu=]] popup: =loadDeadlines()= fills =deadlines=
(every undone =DEADLINE= todo due within =aheadDays=, sorted most-overdue-first), which
a 5-minute =Timer= re-polls (dates roll over on their own) and the toggle-reload
refreshes. =deadlines= is bucketed into =lateItems= (overdue, =delta<0=), =todayItems=
(=delta=0=) and =aheadItems= (=delta>0=) with matching counts and a =hasDue= flag (the
under-line shows only while late+today \gt 0). =gotoItem(file, pos)= opens a headline in
a visible Emacs frame (the popup's "open" action).

** CalendarEvents.qml
*** Description
Google-Calendar *state*, instantiated once in =init.qml= as
=CalendarEvents { id: calEvents }= (mirroring [[*OrgAgenda.qml][=OrgAgenda=]] /
[[*FinanceState.qml][=FinanceState=]], no singletons) and handed to
[[*CalendarMenu.qml][=CalendarMenu=]]. It shells out to [[*gcalbridge.py][=gcalbridge.py=]]:
=read()= loads the on-disk event cache without any network I/O (called on startup and
menu open); =fetch()= / =fetch(a, b)= refresh that cache from Google (the hourly
background =Timer= and the calendar's *refetch* button). Because the bridge caches a
whole date *window*, day membership is filtered client-side: =dayEvents(key)= returns
one day's events (each carries a =days= list so multi-day events show on every day) and
=hasEvents(key)= drives the calendar's blue event dot. =ensureCovers(a, b)= kicks a
fetch only when the shown month grid falls outside the cached window, growing it to
cover both. =loading= drives the refetch spinner; =lastError= / =fetched= / =accounts=
surface status. Best-effort — if the bridge or sign-in fails the lists stay empty and
the calendar still works.

For the *imminent-meeting* notice on the collapsed pill, a =nowTick= =Timer= advances

border = the card colour showing above a rounded-bottom fill); the highlight list is a
*two-column grid* with a fixed 64px verb column, a leader rule, and a single net figure.

Each chapter is a *templated headline sentence* (numbers lead, past tense, exactly one
accent span — e.g. "*402* commits across 11 repos, 38 branches this quarter."), a row of
additive *state chips* (=COMMITS / BRANCHES / PROJECTS / MERGES / PRS= for CODE,
=DONE / MEETINGS / CANCELLED= for AGENDA, each with a 2px accent/neutral top border),
and a ranked *highlight list* (biggest commits by lines changed for CODE; most-clocked
items for AGENDA, with a leader rule to the right-hand figure).

*State (=DoneState.qml=).* Best-effort — an unreachable source leaves its chapter empty,
never in an error state. =code= comes from =gitbridge.py=; =agenda= merges =orgbridge.py=

self-attending, timed, in-window). Configuration gates: CODE needs *both* project dirs
*and* author emails (else an empty-state prompt pointing at Settings › Productivity);
AGENDA needs org enabled *or* any calendar event. Results are cached *per period*
(=_cache=, stale-while-revalidate): switching timeframe reuses the last copy for that
period *instantly* and only re-runs the bridges when it is older than =ttlMs= (5 min), so
the page never lags behind the chips.

*Git backend (=gitbridge.py=).* Local git only for the fast =summary SINCE DIRS EMAILS=
(commits, merges, branches created in-period, active projects, and the top-6 biggest
commits by =add+del=); a configured dir is a repo *or* a root whose immediate children
are repos. PRs are a *separate* =prs SINCE DIRS= command over the =gh= CLI with a
*stale-while-revalidate* cache (=~/.cache/quickshell-pill/done-prs.json=): the cache is
the fast answer, the network is hit only past a TTL (default 900 s), and on failure the
last cached value is served (=stale: true=). =DoneState= fires both in parallel, so the
PR card fills in when the network call returns without blocking the rest of the page.

*Org backend (=orgbridge.py done A B=).* Terminal facts in a date range: a task counts
when it carries a done-keyword *and* a CLOSED stamp inside the range (so it stays counted
forever, on the day it ended); CANCELLED-style keywords split off as their own outcome.
=hours= sums CLOCK ranges whose clock-in falls in the window, and the returned =items=
are the headings ranked by those clocked hours.

*Settings (=ProductivitySettings.qml= + =ListEditor.qml=).* The Productivity page hosts
two =ListEditor='s — a reusable *labelled multi-item string list*: an add control (a
*folder picker* via =kdialog= → =zenity= in =folder= mode, a text field in =text= mode)
plus each current item with a *delete button that asks for inline confirmation* before
removing. Every mutation is emitted *whole* via =changed(list)= so the host reassigns the
=JsonAdapter= array (reassign, not mutate, so it flushes).

level (=max(90, 520 − (level−1)·45)= ms) and it only runs while the pane exists
and the game is neither paused nor over. Rendering is a =Repeater= of 200 cells
bound to a =view= array (board merged with the falling piece), refreshed via a
=rev= counter bumped on every state change. The *next-three* preview also reads
=rev= — the =queue= is shifted/pushed in place (its identity never changes), so
without the =rev= dependency the binding never re-fired and the preview went stale.

*Line-clear flair (deferred clear).* Locking a piece doesn't remove full rows
immediately: it records their indices in =flashRows= and starts =flashTimer=
(260 ms). A per-row =Repeater= flares a bright bar over each (flash-up 70 ms →
fade 190 ms); the piece is already =cur = null=, so gravity idles during the
flash. When the timer fires, =finalizeClear()= drops the rows, scores them,
spawns the next piece, and — for 2/3/4-line clears — pops a centred banner
(=DOUBLE= / =TRIPLE= / accent-coloured =TETRIS!=) that scales-in (=OutBack=) and
fades. Closing mid-flash finalises first (=Component.onDestruction=) so a full,
un-cleared row is never persisted.

The pane *grabs the compositor keyboard* (menu 9 is in =grabsKeyboard=, and
excluded from [[*MenuKbNav.qml][=MenuKbNav=]]): a focused key-sink Item drives it and
=forceActiveFocus()=-es itself on load (so keys reach the game immediately; the
=New game= / =Pause= buttons re-grab focus after a mouse click too). ←/→ move,
↑ or X rotate CW, Z rotate CCW, ↓ soft-drop, Space/Enter hard-drop, P pause, Esc
*saves and closes* (→ the expanded dashboard, or the previous window); on game
over Enter/Space restarts.

*Progress persists.* The whole game (board, falling piece, next queue + bag,
score, high score, paused/over flags) is written to =settings.tetris= (the shared
=launcher.json= adapter) on every lock / pause and on pane destruction, and
reloaded on open — so closing the pane, or restarting the shell, resumes exactly
where you left off.

fall back; the *first* to touch the floor sets =launchX= — the origin for the *next*

top and =balls= increments. *Game over* the moment a shift would push a brick past
the bottom row.

*New rows.* =spawnRow(rn)= fills a random *2–6 of the 6 cells* (=pickFill()=, weighted
toward fewer: 2:5 3:4 4:3 5:2 6:1), each brick's *health = the round number* =rn=.

count grows forever — but at 0.03s spacing even 100 balls launch in ~3s.

=hitBrick()= resolves damage then drains a destruction queue that chains):
- *spray* (=blur_on=, cyan) — each hit also deals its damage to all *8 neighbours*.
- *explode* (=flare=, orange) — when destroyed, wipes its *entire row outright*,
  chaining any other specials caught in it (explosion is destroy-not-damage, so a
  sprayed brick caught in a blast dies without spraying).
- *addball* (=add_circle=, green) — grants one *permanent* extra ball when destroyed.

(fractional-smooth; each sub-step moves ≤ =baseSpeed= 4.6px < a cell, so balls never
tunnel). =speedMul= ramps with time-in-flight and resets each round: 1× until 5s,
→1.5× (5s), →2× (10s), →5× (15s). A =Speed= readout in the stats shows it live.

** SnakeMenu.qml
*** Description
The classic *Snake* (=win.menu === 14=), routed from the Games list
(=onPlayRequested(14) → win.openSnake()=). It *reuses Brick Breaker's pane config*:
a square field on the left, a stats/rules/controls column on the right, the same
*park grip*, and its own size (=snakeWidth= 560 × =snakeHeight= 400 — the side
column is shorter than Brick Breaker's, so the 300×300 field is the tall element).
It *grabs the keyboard* (present in =grabsKeyboard=) and opens *paused*, like the
other games.

*Field.* A =15×15= grid of =cell= 20px cells → a square 300×300 well. There are *no
walls* — the field *wraps*: =step()= takes the head to =(x + dir + cols) % cols= (and
likewise for =y=), so the head that runs off one edge reappears on the opposite one.
Only *self-collision* ends the game.

*Smooth, wrap-aware motion.* The model is grid-stepped (a =sim= timer fires every
=moveInterval= ms) but rendered *continuously* by a shared =prog= 0→1 =NumberAnimation=
restarted each step (=progAnim=, duration = the tick; runs to completion independent of
pause, so pausing settles the snake on its cells). The body is a *fixed index-based*
=Repeater=; each delegate tracks its =from→to= grid cells (a =sync()= on every
=snakeRev=) and renders at =from + dx·prog= along the *shortest toroidal path* (=dx/dy=
are the ±1 wrapped deltas). Because each step does =unshift(head)= + =pop(tail)=, a
segment's =to= is the cell the segment ahead just left, so the whole snake slides one
cell forward. At an edge the primary block slides *off* while a *wrap ghost* (a second
=SnakeBlock= offset by ∓=cols/rows=) slides *in* on the opposite side — the well's
=clip= hides the overhang — so the body crosses a seam one cell at a time. A =snap=
flag lands segments directly on their cells (no glide) on load / new game.

*Immediate growth + travelling bulge.* Eating grows the snake *at once*: the head lands
on the apple and =step()= simply *does not pop the tail* that tick (length +1). The
apple's tile is pushed onto =bulges=; the body segment sitting on a bulge tile renders
*fatter* (the =SnakeBlock= swells, eased by a size =Behavior=), and since the tile is a
fixed world position the lump *stays parked* there while the body slides through it —
until the *tail passes* the tile (=bulges= is filtered to tiles still in the body each
step), when the bulge clears. So an eaten apple visibly *rides down the body as a lump*.
The freshly added tail segment *sprouts* (a =growth= 0→1 =OutBack= scale, gated on
=ready= so load-time segments don't animate), so growth reads as the tail extending, not
a cell popping in.

*Apples.* One at a time, on a random free cell (=spawnApple()=). Each (re)spawn bumps
=appleRev=, driving a *scale-pop* appear animation (=Easing.OutBack=); on eat the old
apple simply *vanishes* and a fresh one pops in elsewhere.

*Controls.* Arrows or *H/J/K/L* steer (=steer()= rejects a reversal into the neck), *P*
pauses, *N* new game, *Esc* closes. On game over, *Enter/Space* restarts. Speed is
*gentle* and rises a little as the snake grows (=moveInterval= = =max(150, 300 −
score·3)=), shown live in the stats.

*Progress persists* to =settings.snake= (body, bulges, dir, apple, score, over, best),
saved on every step and on destruction; =best= is shown in the Games list.

=~/.cache/quickshell-pill/gcal-events.json=.

KDE client's registered =localhost/oauth2callback= redirect permits any loopback port),

*** Description

vad|novad, =POLISH_MODEL= a =claude-*= id or the literal =local=, =LOCAL_MODEL=

- *Polish backend*: the =POLISH_MODEL= id picks the backend (=provider_of=) —
  =local= runs the polish pass through a local ollama model
  (=http://localhost:11434=, no API key, offline, fast); a =gemini-*= id uses the
  Google API, a =gpt-*= id the OpenAI API, and anything else the Claude API. The
  local path needs =ollama serve= running and the model pulled

- *Org agenda*: with =ORG= = =org=, the memo is added to the user's real org
  agenda (matching the Doom capture setup in =doom/config.org=). A =todo= runs an
  LLM extraction (=org-prompt.md=, given today's date) that returns
  ={title, deadline}= — "tomorrow I have to deploy Elvou" ⇒ a =* TODO Deploy
  Elvou= with =DEADLINE:= tomorrow in =~/org/inbox.org=; "go to doctor next week"
  ⇒ deadline +7d. A =note= becomes a heading in =~/org/notes.org=. Written
  through the Emacs daemon (=emacsclient=; direct file append if it's down).

- *CUDA with a real fallback*: =auto=/=cuda= try =float16= on the GPU first —
  the nvidia pip wheels are dlopen-preloaded by absolute path, since
  =LD_LIBRARY_PATH= edits after process start do nothing — and any failure
  falls through to CPU =int8=.
- *Raw text lands first*: the transcript is =wl-copy='d the moment whisper
  finishes, so a failed polish still leaves usable text in the clipboard;
  polish mode then *replaces* the clipboard with Claude's cleanup.
- *Prompt files are user-owned*: =~/.config/quickshell/transcribe/whisper-prompt.md=
  (whisper =initial_prompt= — vocabulary/punctuation bias, ~224-token budget) and
  =polish-prompt.md= (the Claude system prompt). Sane defaults are written on
  first run; they live outside the config dir so a deploy never clobbers edits.
- *API key*: per cloud provider — the provider's env var if set
  (=ANTHROPIC_API_KEY= / =GOOGLE_API_KEY= / =OPENAI_API_KEY=), else the keyring
  entry =<provider>/pill-transcribe= (KWallet via the venv's =keyring=; stored
  from the pill's Transcribe tab).
- *It reports for itself*: success and failure notifications are sent from here
  with =notify-send -a Transcribe= (the pill renders them with the custom
  resident styling — see [[*NotificationView.qml][=NotificationView=]]), so a
  failure surfaces even if the shell reloads mid-run. One JSON line
  ={"ok": …, "mode": …, "error": …}= goes to stdout for the pill's state machine,
  and the wav is deleted on every path.

** init.qml
*** Description
The entry point and long-lived root: it owns the per-monitor windows, the stage
machine, virtual desktops, the taskbar/tray UI, action bursts, and hosts the menus
and launcher. Sibling =.qml= files are used as component types via QML's implicit
directory import; =Theme= is instantiated once here and passed to each menu as
=theme= (no singletons).

*Window & input model.* =Variants { model: Quickshell.screens }= makes one
full-screen layer-shell =Overlay= =PanelWindow= per monitor that reserves no space.
The window =mask= governs input: collapsed/hovered → only the pill rectangle catches
clicks (the rest passes through); open/launcher/right-click → the whole window, where
a backdrop =MouseArea= swallows outside clicks to close (never passed through);
fullscreen-hide (=win.fsHide=, set while a fullscreen window is focused and the pill
is at true rest) → an empty region, so the window is fully click-through and the pill
fades to opacity 0. A resting notification still surfaces over fullscreen (=notifRest=
overrides =fsHide=, and its floating deck's rect joins =pillRegion= while shown — see
[[*NotificationDroplet.qml][=NotificationDroplet=]]).

*Stages.* A single =pill= =Item= animates =width=/=height= between stages via
=Behavior=, cross-fading content layers per stage:
1. *collapsed* (56×28): =hh:mm=.
2. *hovered* (=dash=, 520×116): two balanced rows separated by a hairline rule —
   Row 1 date/time (serif clock over a mono date label) with the virtual-desktop
   dots stacked beneath it (left) | grouped app icons (right); Row 2 a launcher
   button (left) | system tray + status icons
   (network/volume/bluetooth/battery/notifications) (right). The launcher, status
   icons and tray icons are the same square =iconCell= size at =iconSpacing= apart;
   the app tiles match the cell but are spaced 1.5× wider (their icons run larger).
   All of them share a *single* hover square (=hoverInd=) that slides from item to
   item as the pointer enters each (growing a little behind the larger app tiles).
   It *stays* on the last item once the pointer leaves and only resets to the
   launcher icon when the dashboard collapses (=win.hoverItem= / =hoverEnter=).
3. *open* (470 tall): control panel. The two dashboard rows *fade out* so the menu
   fills the pill from the top; a =Loader= shows the menu for =win.menu= (default
   4 = notification history). Each menu carries its own =MenuHeader= (back chevron +
   serif title); the chevron collapses the panel via =closeRequested()=, returning
   to the dashboard where another status icon can open a different menu.
4. *launcher* (600×470): the launcher takes the menu pane's place — the rows fade
   out here too (see [[*Launcher.qml][§ Launcher.qml]]).

*Movable idle pill.* The resting pill is *draggable anywhere on screen* by its body
(an =idleDrag= =DragHandler= alongside the capture one; it only steals the grab past
the drag threshold, so a plain click still reveals the dashboard / opens deadlines).
The spot is *per-session only* — never persisted, so each launch starts top-centre —
and it applies *only while idle/collapsed* (=idleMoved && !dash=). A *middle-click* on
the resting pill (=idleReset()=) sends it home: clearing =idleMoved= re-points
=pillCenterX= at screen-centre and =y= at 0, and both glide there via their Behaviors
(=Behavior on y= is enabled for every non-drag transition for exactly this) while the
wings grow back — one smooth motion, not a snap. The moment the pill
*expands* (dashboard / any menu / launcher / capture / voice) it animates back to the
top-centre home so panels always open from the same predictable place; *collapsing*
restores the dragged spot. The expand/collapse move is *one fluid motion*, not
grow-then-slide: =pill.x= is DERIVED as =pillCenterX - width/2= with *no Behavior of its
own*, and it is the target *centre* (=pillCenterX=) that animates. So the width grows
*symmetrically about the centre* (not from the left) while the centre itself glides to
screen-middle, both on the same =theme.anim= curve. (Binding =x= straight to the
animating =width= made its Behavior chase a moving target and lag a whole duration
behind — width finished first at the old left, then x slid.) The dragged spot is tracked
as a centre too (=idleCenterX=); =pillCenterX= freezes while either drag is live so the
pill tracks the pointer 1:1. Like the capture pill it *re-attaches* when dropped within
=idleSnapY= of the top edge (=idleAttached=, snapped flush to =y=0= with its concave
*wings* at the dragged x); dropped lower it *floats* fully rounded with no wings
(=idleFloating=). A shared =pillFloating= (=capFloating || idleFloating=) drives the
=PillSurface= wing/radius morph for either pill. Because the notification droplet +
deck, the action burst (a child of =pill=),
and the Agenda popup all read =pill.x/pill.y=, they follow the parked pill and drop
*below* it — at the top-centre home this is identical to the old screen-centre.

*Keyboard focus.* The surface grabs the keyboard only when it genuinely needs it
(=win.grabsKeyboard=): the launcher or clipboard menu is up (both auto-focus a search
field and want arrow-key nav), or *some* editable field inside the pill currently has
focus (wifi password, notification reply) — detected by =kbInputFocused=, which reads
the window's active-focus item via a small =kbProbe= =Item= (=Window.activeFocusItem=)
and checks its =objectName === "pillKbInput"=. Keyboard-nav mode (=win.kbNav=, via
the =expand= IPC — see below) also grabs for its whole stay. In all those cases the
surface takes =Exclusive=; otherwise it stays =None=. So a menu you're only clicking toggles in never
steals focus from the active window, and a field pulls the keyboard the moment it takes
focus (its own =focus:= or a click) with no stray grab. KWin does *not* restore focus
when a layer surface releases the keyboard, so the pill remembers the last real active
window (=lastActiveWindow=, from =winbridge=) and =restoreFocus()= re-activates it via
the KRunner =Run= when the pill is dismissed *without* launching — but *only* if it was
actually grabbing (=wasGrabbing=), so dismissing a focus-less menu doesn't disrupt the
active window; launching an app skips the restore.

*Global shortcut (Meta+D).* Quickshell's =GlobalShortcut= is Hyprland-only, so the
launcher shortcut rides the KWin script in =winbridge.py= (see [[*winbridge.py][§ winbridge.py]]):
its =\{event:"launcher", screen\}= line becomes the =launcherShortcut(screen)= signal,
and each monitor toggles its launcher if the screen matches.

*Clipboard shortcut (IPC).* The clipboard-history menu is opened by an =IpcHandler=
(=target: "pill"=) instead of the KWin script, so it can be bound from KDE's own
shortcut settings: add a *Custom Shortcut* (System Settings ▸ Shortcuts) running
=qs -p /home/<user>/.config/quickshell/pill/init.qml ipc call pill clipboard= and
assign it e.g. *Super+V* (free it from Klipper first). The call fires
=clipboardShortcut("")= → =openClipboard()= on every pill (an empty screen name);
=clipboardOn(screen)= targets one monitor. Re-firing while it's up toggles it shut.

*Notifications shortcut (IPC).* The same =IpcHandler= exposes =notifications= /
=notificationsOn(screen)=, which open (or toggle shut) the notification history pane
(=win.menu === 4=) — mirroring =clipboard= — plus two one-key sweeps that need no
menu: =dismissNotifications= (=notifs.dismissAll()=) clears every popup off the screen
but *keeps* them in history (the "I'm busy, not now" sweep — the unread strip/badge
stay), while =clearNotifications= (=notifs.clearAll()=) wipes the whole history. Bind
*Custom Shortcuts* (System Settings ▸ Shortcuts) running
=qs -p …/init.qml ipc call pill notifications= (e.g. *Super+N*),
=… ipc call pill dismissNotifications=, and =… ipc call pill clearNotifications=. The
pane grabs the keyboard when open, so it can be triaged entirely from the keyboard
(arrows / Enter / =i= / =x= / Delete / Escape — see
[[*NotificationHistory.qml][§ NotificationHistory.qml]]).

*Expanded view + keyboard nav.* Clicking the collapsed pill *and* the =expand= /
=expandOn(screen)= IPC both open the expanded dashboard in *keyboard-nav mode*
(=win.kbNav=) — the state where the pill grabs the keyboard without a text field
(so arrows/Escape/menu-jumps work the moment the dashboard appears, and any pane
opened from it — e.g. Tetris — keeps the keyboard). Bind the IPC to a shortcut with
=qs -p …/init.qml ipc call pill expand=. Bind a *Custom Shortcut* running
=qs -p …/init.qml ipc call pill expand=. Focus rides the shared hover square
(=win.hoverItem=), so mousing over any item re-focuses it; the clock/date block is
focused first. Arrows move between the zones exactly as laid out — clock → right →
taskbar tiles; clock → down → launcher icon; taskbar → down / launcher → right →
the Row-2 strip (tray icons first, then the status icons, one left/right run);
Enter "clicks" the focused item (each dashboard item carries a =keyClick()=).
f/c/n/w/v/b/t jump straight to finance / calendar / notifications / network / volume
/ bluetooth / tetris as a first level; f/c/n/w/v/b also work inside the calendar menu. Open
menus get generic keyboard focus from [[*MenuKbNav.qml][=MenuKbNav=]] (back button
focused first, arrows spatial, Enter clicks, tab bars step left/right; the
notification and clipboard panes keep their own richer handling, and the calendar
grid stays mouse-only). *Escape steps back*: menu → expanded dashboard → closed
(restoring focus to the previous window). The mode ends whenever the pill fully
closes (Escape, backdrop click, launching an app). The notification / clipboard /
launcher IPC commands are unchanged: opened that way (no kbNav), their Escape
still closes the pill outright.

*Brightness shortcut (IPC).* The same =IpcHandler= exposes =brightnessUp= /
=brightnessDown=, which step the *active monitor's* screen brightness by ≈5% via the
shared [[*Brightness.qml][=Brightness=]] state (KDE's =org.kde.ScreenBrightness=, i.e.
the internal backlight *or* an external monitor over DDC/CI). The active monitor is
the focused window's output (=root.activeScreen=, from =winbridge=). Bind two *Custom
Shortcuts* (System Settings ▸ Shortcuts) running
=qs -p /home/<user>/.config/quickshell/pill/init.qml ipc call pill brightnessUp= and
=… brightnessDown= — assign e.g. the =Monitor Brightness Up/Down= keys (free them
from Plasma's built-in brightness action first, since that one drives all displays
at once). =brightnessUpOn(screen)= / =brightnessDownOn(screen)= target a named output
explicitly. Each step also flashes a *level burst* (see below).

*Volume shortcut (IPC).* The same =IpcHandler= exposes =volumeUp= / =volumeDown= /
=volumeMute=, which step or mute the *active speaker* — the default Pipewire sink,
i.e. the device with the check in the [[*VolumeMenu.qml][volume menu]] — by ≈5% via
=Quickshell.Services.Pipewire= (=Pipewire.defaultAudioSink.audio=), and flash a level
burst. Bind three *Custom Shortcuts* (System Settings ▸ Shortcuts) running
=qs -p …/init.qml ipc call pill volumeUp= / =… volumeDown= / =… volumeMute= to the
=Volume Up/Down/Mute= keys — *free those keys from Plasma's built-in Audio Volume
actions first*, so only our burst shows (no double OSD) and nothing else moves the
volume.

*Scroll to nudge (wheel).* A topmost =MouseArea= (=z:100=, =acceptedButtons:
Qt.NoButton= so clicks + hover fall straight through — it only claims the wheel)
lets you scroll *anywhere over the pill* — the resting clock pill OR the hovered
dashboard — to raise/lower the active speaker's volume. The step scales by the
actual =angleDelta= (120 eighths-of-a-degree = one notch = 5%) so hi-res /
free-spinning wheels move smoothly. Gated OUT of the open control panel / menus,
the launcher, a ctx menu, the notification morph, and the action-burst /
voice-recorder takes (those scroll their own content or shouldn't hijack the wheel).

*Level burst.* Both the brightness and volume shortcuts render through one *level*
burst kind ([[*ActionBurstPill.qml][=ActionBurstPill=]]): a two-column mini-pill —
glyph on the left, title (=Brightness= / =Volume= / =Muted=) over a progress bar on
the right — whose fill animates from the old value to the new across the burst's
animate phase (=startLevelBurst(icon, title, from, to)= sets the payload; the bar
sits at =levelFrom= until =phase === 2=, then eases to =levelTo=).

*Taskbar.* =appGroups= builds the taskbar model: *pinned* apps first (in
=settings.pinned= order, running or not), then the remaining *open* apps grouped by
*app class* and ordered by *open time* (winbridge stamps each window with a stable
open-order =seq=). A pinned app that's also open merges its windows into its pinned
tile. Each tile carries ={ key, icon, entry, wins, pinned }=; a count badge for ≥2
windows and an underline that shows only while the app is *running* (accent when a
window is active). A *pinned-but-unopened* tile has no windows, reads dimmed, and
left-clicking it *launches* the app (=taskbarActivate=: launch if not running, else
=cycleGroup=). Icons resolve through =DesktopEntries.heuristicLookup= (desktop-file
name → class → KRunner icon name). Tiles *drag-to-reorder within their own section*
(pinned among pinned, open among open — a drag never crosses the boundary, so it
can't pin/unpin); on release =taskbarReorder= persists the pinned order to
=settings.pinned= and keeps the unpinned order for the session (=root.unpinnedOrder=).
*Pinning is only offered from the app menus* — the launcher's [[*AppMenu.qml][=AppMenu=]]
(Pin/Unpin to taskbar, alongside the favourite toggle) and, for open apps, the
taskbar's own menu. Right-click opens the [[*AppContextMenu.qml][=AppContextMenu=]]
*inside the pill* (like the control-panel menus, not a floating popup): the app name,
its =DesktopEntries.heuristicLookup(icon).actions=, then the KWin window actions (Move
to Desktop / Minimize / Maximize / Keep Above/Below), a *Pin/Unpin to taskbar* row,
and Close (a not-running pinned app shows only the Pin row). Selecting a window action
calls =root.windowAction(group, verb)=, which asks =winbridge='s =org.kde.pill Action=
method to run a one-shot KWin script against *every* window in the group. The pill
sizes to the menu's =implicitHeight= in ctx mode and the =mask= expands full-screen
while it's open (=win.ctxGroup=); the two dashboard rows fade out like they do for an
open menu.

The *system-tray* icons share the same in-pill ctx mode. Right-clicking a tray icon
(=SystemTrayItem.hasMenu=) opens its StatusNotifierItem/DBusMenu as a
[[*TrayMenu.qml][=TrayMenu=]] (=win.trayItem=) rendered exactly like the app menu — not
the fragile native =display()= popup — walking the menu handle with =QsMenuOpener= (see
[[*TrayMenuLevel.qml][=TrayMenuLevel=]]). =win.ctxMode= (=ctxGroup !== null || trayItem
!== null=) is the shared predicate that both menus drive the pill mode / mask / fade
through, while each menu keeps its own =Loader=. Left-click still =activate()=s (or opens
the menu for =onlyMenu= items); a menu-less item falls back to =secondaryActivate()=.

*Virtual desktops.* Three =Process= blocks drive =gdbus= against =org.kde.KWin
/VirtualDesktopManager=: fetch the =desktops= list (a regex parses the tuples), fetch
=current=, and =gdbus monitor= =currentChanged= to stay live; =switchDesktop(id)=
sets the writable =current= property.

*Action bursts.* A transient burst briefly (~1s) *replaces the clock inside the resting
pill*, which resizes around it, then reverts. Driven from =root= so every monitor shows
it (=burstDesk= / =burstLang= / =burstLevel= / =burstPhase=; one =Timer= runs settle
100ms → animate 300ms → settle 600ms, and *restarts from the top on every new burst* —
so several bursts share one life and *clear together* ~1s after the last). Live bursts
are tracked in a *=burstModel= =ListModel=* (=burstAdd()= inserts / lifts each kind to
index 0, newest first); it is cleared when the group life ends. The presentation lives
in the pill, which *stays pinned to the top edge* (no 6px float — a burst is the pill
now, not an overlay): the =PillSurface= stays solid through a burst (=showBurst= joins
the solid-fill set) and keeps whatever wings/rounding the pill currently has; the
=CollapsedPill= clock *revolves away* (folds down +90° about its top edge, fading) while
=burstLoader= (z 5) hosts the [[*ActionBurstPill.qml][=ActionBurstPill=]] *column* whose rows
revolve in from above; the pill's =width=/=height= animate the resize (width from the
centre via =pillCenterX=). Multiple bursts *stack vertically, newest on top*, the new
one rolling the earlier rows down. A burst takes over only the resting pill
(yields to hover/open/launcher/right-click). It is *independent of notifications*: the
resting droplet deck is left untouched and simply sits below the now-taller pill — the
two animate separately. While a *capture* owns the pill the burst can't replace the
controls, so it floats just *below* them in its own =boxed= surface instead.
Two events fire bursts, each guarding its initial value on startup:
- *desktop switch* (=onCurrentDesktopChanged=) — a filled dot slides from the old
  slot to the new across the animate phase; the hovered Row-1 dots use the same slide.
- *layout change* (=onKbIndexChanged=) — shows =from → to= (e.g. =US → FA=) with the
  arrow flashing. Layouts come from KWin's =org.kde.keyboard /Layouts= (custom label
  if set in System Settings, else the uppercased code).
- *volume / brightness* (=startLevelBurst=, fired by the volume/brightness IPC
  shortcuts) — the =level= kind: an icon + title over a progress bar that animates
  from the old value to the new (see the shortcut notes above).

*Notifications & launcher hosting.* The =Notifications= object (=notifs=) and the
shared =appList= (=DesktopEntries.applications=, =noDisplay= filtered, name-sorted)
are built once here and shared with every monitor. The collapsed pill *morphs* into
the active-popup deck when a notification arrives and the pill isn't open (the clock
hides and =pill.height= tracks the deck); while open/launcher/app-menu the deck floats
*below* instead. The launcher field is focused + cleared on each open and its focus
dropped on close (so the pill releases the keyboard).

*Privacy indicators.* At rest the pill also flags a live *camera* (any process
holding a =/dev/video*= node open, polled every 2s with =fuser=) or an active
*screen capture* (a =Stream/Output/Video= PipeWire node published by
xdg-desktop-portal / KWin while the screen is shared or recorded). A hot mic is
intentionally *not* flagged (an unmuted mic is a routine resting state, so it was
more noise than signal). Either drops the idle translucency — the collapsed pill
goes solid (real surface + border, no gradient, full-opacity clock) — and shows an
indicator next to the clock: the camera as a glyph, screen recording as a *big red
dot that pulses (emits a fading ring) once every 5s*; they sit side by side when
both are live, widening the pill. The glyphs *pop in* and *shrink out* like the
action bursts (scale overshoots on appear via =OutBack=, the slot width animates so
the clock slides over). A live camera or an active screen capture also keeps the
pill visible over a fullscreen window, where it would otherwise hide.

**** init.qml — voice recording
The voice-to-text state machine: =idle → recording → transcribing → idle=,
root-owned (ONE recording however many monitors; the per-window =voiceMorph=
just renders it). Driven by the =voiceToggle= / =voicePolishToggle= IPC calls —
both *start* a take when idle; when recording, the call that *stops* it picks
the route (raw transcript vs Claude polish), so you can start with either combo
and decide at the end. The floating X ([[*init.qml — per-monitor overlay window][overlay]])
cancels and discards.

Recording is =pw-record= at 16 kHz mono s16 (what whisper wants) into =/tmp=.
With noise suppression on, an RNNoise filter-chain
([[*source-rnnoise.conf][=source-rnnoise.conf=]]) is spawned first and the
recorder targets its =rnnoise_source= node the moment it appears on the
PipeWire graph — a 1.5s fallback timer degrades to the raw default source so a
missing plugin never wedges a take. Stopping SIGTERMs =pw-record= (a clean stop
finalizes the WAV header — never flip =running=false=, which risks a corrupt
wav), and =onExited= chains into [[*voicebridge.py][=voicebridge.py=]] (venv
python). The bridge posts its own success/failure notifications; the QML only
falls back to a =notify-send= when the bridge died without reporting (e.g. the
venv doesn't exist yet — run =setup-transcribe.sh=). Double-toggles while
transcribing are no-ops; =voiceDiscard= short-circuits every exit handler on
cancel.

* Editing & deploying

The code lives in [[file:pill/][=pill/=]] (this repo); the live config at
=~/.config/quickshell/pill/= is a *copy* the running pill loads from. There are
no symlinks and no tangling — editing a repo file changes nothing live until you
deploy, so you can work in peace:

1. Edit files in =pill/=.
2. Test with =pill/check.sh= — validation only, touches nothing live (python
   =ast= parse, =bash -n=, and a headless =QT_QPA_PLATFORM=offscreen qs -p
   init.qml= load that compiles and type-checks every referenced component).
   This is the *only* test step AI agents may run.
3. Run =pill/deploy.sh= — runs =check.sh=, then copies *only the changed files*
   to the live config; the running pill picks the change up on its own
   (Quickshell watches its config files). *User-only*: agents never deploy,
   even if asked — they stop and ask me to run it.

Never edit =~/.config/quickshell/pill/= directly — the next deploy would
overwrite it. If a live file was hot-fixed in place, copy it back into =pill/=
first (=deploy.sh= prints a note for any live file the repo doesn't know about).

Two historical notes that still matter for reading the sources: =init.qml= and
=Launcher.qml= were assembled from org noweb chunks, so their subsections below
(=**** init.qml — …=) each describe one region of the now-monolithic file; and
launching the pill makes =winbridge.py= load a small KWin script
(=quickshell-pill-active=) which is unloaded when the bridge exits.

Validation gotchas (offscreen =qs= can't instantiate PanelWindow children, Scope
harnesses, FloatingWindow screenshot rig, …) are collected in
[[file:pill/README.md][=pill/README.md=]] and the agent memory =quickshell-qml-validation=.
